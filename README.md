# 家庭健康记录

一个适合家庭使用的健康记录 Web 应用。可以预设家人信息，记录自己或家人的体温、症状、用药、就医与护理情况，并上传病例单，并按时间查看、修改。网站支持添加到手机桌面，以独立窗口运行。

后端使用 Python、Flask、Gunicorn 和 SQLite，前端使用 HTML、CSS 与少量 JavaScript。应用使用账号密码、服务端可撤销会话、CSRF 防护和 HTTPS 反向代理；同一部署中的账号共享全部家庭记录。

## 功能

- 设置家人称呼、关系、出生日期和健康备注；记录时下拉选择家人。
- 记录和编辑病程，上传病例单，按时间分页查看；并发编辑时提示冲突。
- 登录过期时保留当前页面上尚未保存的输入，重新登录后可继续保存。
- 支持安装为 Web 应用。健康记录需要联网访问；离线只显示联网提示，不在 Service Worker 中缓存记录或表单。
- 使用 SQLite 在线备份，校验快照完整性；备份任务不启动已停止的应用。

## 本地运行

需要 Python 3.12 或更新版本。以下命令只创建本机测试数据，首次生成密钥时不会覆盖已有密钥：

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
export HEALTH_DATA="$PWD/data"
mkdir -p "$HEALTH_DATA"
chmod 700 "$HEALTH_DATA"
.venv/bin/python -c 'import os; p=os.path.join(os.environ["HEALTH_DATA"],"session.key"); fd=os.open(p,os.O_WRONLY|os.O_CREAT|os.O_EXCL,0o600); os.write(fd,os.urandom(32)); os.close(fd)'
.venv/bin/python app.py set-password admin
.venv/bin/gunicorn --bind 127.0.0.1:18765 --timeout 180 'app:create_app()'
```

访问 `http://localhost:18765/`。应用设置了 Secure Cookie；如果浏览器不接受 localhost 的安全 Cookie，使用本地 HTTPS。`data/` 和数据库文件不应提交到版本库。

## 配置与部署

- `HEALTH_DATA`：运行数据目录；默认 `/var/lib/child-health`。目录中包含数据库和 `session.key`，必须限制文件权限，并妥善备份密钥。
- `HEALTH_TRUSTED_HOSTS`：逗号分隔的允许访问的主机名，默认只允许 `localhost,127.0.0.1`。公开部署必须显式设置自己的域名，例如 `HEALTH_TRUSTED_HOSTS=journal.example.org`。不要填 URL、协议或通配的全部主机。
- 生产环境应使用 HTTPS，Gunicorn 只监听本机回环地址；示例 systemd 单元可从 `/etc/child-health/child-health.env` 读取环境变量。示例服务路径、系统账号和备份目录需要在部署前创建并核对。
- 当前反向代理设置只信任**一层**会设置 `X-Forwarded-For` 和 `X-Forwarded-Proto` 的可信代理。部署拓扑变化时，需同步调整 `ProxyFix` 配置，禁止直接暴露后端端口。
- 记录时间使用 `Australia/Melbourne` 本地时间；如果用于其他时区，需要在应用、备份脚本、定时器和页面文案中同步调整。夏令时切换期间的本地时刻可能有歧义。
- 备份脚本默认读取 `/var/lib/child-health/health.sqlite3`，保存至 `/data/child-health-backups`。这些路径也出现在 systemd 单元中，调整时需一起修改。备份默认保留在同一台机器上，建议自行设置加密异地备份及监控。

本公开备份移除了原部署的专用域名；`HEALTH_TRUSTED_HOSTS` 是为公开版本增加的配置项。现有生产部署不因这个仓库而自动改变。

## 测试

```sh
.venv/bin/python -W error::ResourceWarning -m unittest discover -s tests -v
node tests/test_service_worker.cjs
```

测试使用临时 SQLite 数据库及合成账号，不需要生产数据。Service Worker 测试验证网络请求处理、离线提示与不使用 Cache Storage。

## 家人与病例单


登录后点击顶部“设置”，添加或编辑家人称呼、与我的关系、出生日期及健康备注。新增记录使用家人下拉菜单；在新标签页添加家人后，返回原表单会更新选项并保留填写内容。升级时，旧记录的称呼自动建立家人关联，所有原字段及账号保持不变；修改家人称呼后，列表显示当前称呼，原记录内的称呼快照仍保留。

新增或编辑记录时，可上传 PDF、JPG/JPEG、PNG、WebP 病例单；每个最多 10 MiB，每次最多 3 个，每条记录累计最多 20 个。文件扩展名与签名需一致；校验不是病毒扫描或完整文件解析。附件与记录在一个数据库事务中保存，冲突或写入失败时都不保存；验证失败需重新选择文件。仅登录后可下载，强制作为附件提供，不内嵌执行上传内容。

附件原文以 BLOB 保存在同一个 SQLite 数据库中，现有每日备份同时包含家人、记录和病例单，不需要额外文件目录。病例单会增加数据库及保留快照占用，应监测剩余空间。未提供家人或附件删除入口。后台请求超时调整为 180 秒，以便手机网络上传；应用仍需联网使用。

升级前先备份现有数据库，部署全部代码后运行 `app.py init-db`（systemd 启动前也会执行）。迁移为事务内的增量更新，不清空原记录和账号。配置文件和密钥应保留原值。回退代码时保留升级后的数据库，不自动恢复旧快照覆盖新记录。

## 历史记录


登录后点击右上角“历史记录”。默认显示本月日历，日期格标记符合筛选的记录数量；可切换月份、跳转指定月份、回到本月，点击日期查看当天记录，或切换为全部历史列表。列表和日历结果每页最多 50 条，分页会保留筛选条件。

关键词最多 200 字，按连续文字匹配家人当前称呼/关系、原记录称呼、体温、症状、用药、就医护理、备注及病例单文件名；英文 ASCII 大小写不敏感，百分号和下划线作为普通字符匹配。不解析病例单正文或执行 OCR。可组合家人和起止日期，日期范围包含开始与结束当天，沿用墨尔本当地记录时间。搜索按钮查询全部历史；从搜索结果切换日历时，默认定位到最近有匹配记录的月份，明确指定月份时保持该月。

历史页仍需登录，响应 no-store，无额外脚本、外部日历服务或数据结构迁移。查询只读取记录及附件元数据，不加载病例单 BLOB，不修改记录。搜索条件使用 GET 表单，会出现在当前 URL / 浏览器历史中；不要将带有私人关键词的链接公开分享。

## 彩色事件月历


月历使用连续网格和事件条目：有记录的日期显示家人色点，格内直接显示家人称呼和简短摘要，桌面同时显示时间。每位家人自动分配固定颜色，改称呼、筛选、切月或正常添加家人时既有家人配色保持稳定；图例和记录条目同时保留称呼，点击图例可筛选或取消筛选。

每个日期桌面最多预览 3 条，手机最多 2 条，多余显示“还有 / +N 条”。点击日期或更多入口查看当天全部记录，点击事件进入对应记录。预览按时间正序显示，全文仍在记录详情中；摘要只截取已有字段，不修改原内容。月历中的搜索面板默认收起，可点击展开；列表模式保持展开。

配色通过须登录的 `/calendar-colors.css` 提供，只包含数字选择器和生成的颜色，不含家人称呼或记录内容；保持既有 CSP，不依赖行内样式。预览查询不读取病例单 BLOB，最多取每月每天 3 条，不随列表分页改变。该查询使用 SQLite 窗口函数，运行环境需要 SQLite 3.25 或更新版本（现有 Ubuntu 环境已验证）。没有数据库结构迁移或新的 Python 依赖。

## 症状快捷选项

新增和编辑记录支持带图标的症状多选：低烧、发热 38°C、高烧 39°C、呕吐、流鼻涕、咳嗽。保留补充说明和准确体温输入；保存后可编辑、搜索及在日历摘要查看。不依赖 JavaScript 勾选，旧表单兼容，无数据库结构迁移。
